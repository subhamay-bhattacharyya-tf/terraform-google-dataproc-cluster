## Usage

```hcl
module "dataproc_cluster" {
  source  = "subhamay-bhattacharyya-tf/<repository-name>/google"
  version = "~> 1.0"

  # Required inputs
  environment  = "prod"
  project_code = "myproject"

  dataproc_cluster_config = {
    base_name            = "spark-etl"
    image_version        = "2.1-debian11"
    worker_num_instances = 4

    # Optional
    optional_components     = ["JUPYTER"]
    enable_http_port_access = true
    idle_delete_ttl         = "3600s"
    labels                  = { env = "prod", team = "data-eng" }
  }
}
```

## Notes & Caveats

> **Destructive operation:** Destroying this module deletes the Dataproc cluster and all its nodes. Ensure all running jobs are complete and any persistent data is saved to GCS before running `terraform destroy`.

- Setting `preemptible_worker_num_instances > 0` reduces cost but preemptible nodes can be reclaimed by GCP at any time — use only for fault-tolerant workloads.
- Setting `idle_delete_ttl` is strongly recommended for development clusters to avoid unnecessary costs.
- `master_num_instances = 3` enables High Availability mode; changing this after cluster creation forces replacement.
- This module does not manage Dataproc autoscaling policies — create a `google_dataproc_autoscaling_policy` resource separately and pass its name via `dataproc_cluster_config`.

## CI / Workload Identity Federation Setup

The Terratest job authenticates to GCP via [Workload Identity Federation](https://cloud.google.com/iam/docs/workload-identity-federation) (service account impersonation). If the job fails with `Permission 'iam.serviceAccounts.getAccessToken' denied`, grant the WIF pool principal the required IAM binding:

```bash
gcloud iam service-accounts add-iam-policy-binding \
    "<service-account-email>" \
    --project="<gcp-project-id>" \
    --role="roles/iam.workloadIdentityUser" \
    --member="principalSet://iam.googleapis.com/projects/<project-number>/locations/global/workloadIdentityPools/<pool-name>/attribute.repository/<github-org>/<repository-name>"
```

The three repository variables required by the CI workflow are:

| Variable | Description |
| --- | --- |
| `GCP_PROJECT_ID` | GCP project ID passed as `GOOGLE_CLOUD_PROJECT` to Terratest |
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | Full WIF provider resource name |
| `GCP_SERVICE_ACCOUNT` | Service account email to impersonate |
